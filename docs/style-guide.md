# 写作规范

模板解决「看起来专业」，这份规范解决「读起来专业」。两条都做到，报告才立得住。

## 1. 摘要：五句话

一段话，150--250 词，按顺序回答：

1. **是什么**：我们给出 X，一个……的系统/模型/方法。
2. **多大**：规模、数据量、上下文长度、参数。
3. **怎么做的**：两三个关键设计，不要罗列全部。
4. **赢在哪**：最硬的 2--3 个数字，写清对比对象。
5. **在哪拿**：代码、数据、检查点的链接。

反面例子：「取得了显著提升」「性能优异」——没有信息量的形容词一律删掉。

## 2. 数字

| 场景 | 排版结果 | 源码写法 |
|---|---|---|
| 千分位 | 32,768 | `32{,}768` |
| 乘号 | 8×H100 | `8$\times$H100` |
| 数值与单位 | 38 ms | `38\,ms` |
| 百分号 | 62.4% | `62.4\%` |
| 精度 | 62.4 与 61.0 | 同一张表不要混用 `62.40` |
| 提升幅度 | +2.1 points over the 7B baseline | 写清基线，不要只写 `+2.1` |

第三条最容易被忽略：`38ms` 会在断行处被拆成「38」和「ms」，读起来像两个东西。
`38\,ms` 用细空格把数字与单位绑住。

## 3. 表

- 一律 `booktabs` 三线表：`\toprule` / `\midrule` / `\bottomrule`，**不要竖线**。
- 表题在表上方（类里已设 `position=top`），图题在图下方。
- 最优 `\best{}` 加粗，次优 `\second{}` 下划线，并在 caption 里说明含义。
- 每张表都必须在正文里被 `\cref` 引用，否则删掉它。
- 宽度别超过版心；超了先删列，再考虑 `\small`，最后才 `\resizebox`（会改字号，慎用）。

## 4. 图

- 矢量优先：TikZ 直接画，或 matplotlib `savefig("fig.pdf")`。
- 位图至少 300 dpi，不要把 PDF 截图再贴回去。
- 图内字号 ≥ 7pt（缩放后），否则打印看不清。
- 一张图只讲一件事；子图用 `(a)` `(b)` 并在 caption 里解释。
- 首屏放主结果图：读者 30 秒内能判断这份报告值不值得读。

## 5. 引用

- 用 `\citep{}`（括号引用）与 `\citet{}`（作主语），不要手写 `[1]`。
- 基准测试引原始论文，不要引二手博客。
- `refs.bib` 里 `title` 用 `{}` 保护大小写：`{DeepSeekMoE}`，否则会变成 `Deepseekmoe`。
- 中文里引用章节用 `\secref{}`（「第 3 节」），图表用 `\cref{}`（「图 1」）。

## 6. 语气

- 主动语态、第一人称复数：「我们训练」「我们观察到」。
- 失败也要写：「小规模尝试提升了 X 但降低了 Y」比藏起来可信。
- 不夸大：除非数字真的全面领先，否则用「持平」「可比」而不是「超越」。
- 不写「首创」「最优」除非有第三方可比数据。

## 7. 长度参考（8--20 页的报告）

| 章节 | 建议篇幅 | 必须有的内容 |
|---|---|---|
| 引言 | 0.5--1 页 | 问题、3 条贡献、全文导航 |
| 方法/结构 | 1--3 页 | 结构图 + 配置表 + 两三个关键取舍 |
| 实验/结果 | 2--3 页 | 主表 + 消融 + 评测设置 |
| 结论 | 0.3 页 | 结论 + 可迁移的经验 |
| 局限 | 0.5 页 | 逐条具体，不要一句「受限于算力」 |
