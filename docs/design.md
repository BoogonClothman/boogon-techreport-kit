# 设计说明

记录这份模板为什么长这样，以及哪些事情**刻意不做**。改动之前先读一遍，可以省一次返工。

## 1. 一个类文件，而不是一堆 `.sty`

```
boogonreport.cls   ← 唯一必须随项目走的文件
```

理由很实际：工具包会过期，项目不会。半年后回到某个项目，只需要记住「复制一个文件」，
而不是「装某个模板包、再找它的 `.sty` 依赖」。代价是类文件会变长（约 430 行），
但这 430 行是一次性成本。

## 2. 单栏、宽版心、块状段落

- **单栏**：技术报告主要在屏幕上读，双栏必须放大；单栏的代价是每页字数少，
  所以定位是 8--20 页的报告，不是学位论文。
- **版心 160 mm**：左右 25 mm，比 Bringhurst 的 66 字符略宽。理由：公式、代码、
  宽表格比纯散文多，窄一分就多折一行。
- **段落不缩进、段间半行**：屏幕阅读更利于跳读。中文论文若要求缩进，
  改两行即可（见 `docs/adoption.md`）。

## 3. 两种字体管线，一套观感

| | 英文 | 中文 |
|---|---|---|
| 引擎 | pdfLaTeX | XeLaTeX |
| 文本 | URW Palladio（T1） | TeX Gyre Pagella（TU） |
| 数学 | Pazo Math | Pazo Math |

Palladio 与 Pagella 是同一设计的两份实现（Type1 / OpenType），肉眼几乎无法区分，
但字符覆盖不同：Pagella 带 `→ ≥ µ`，Palladio 不带。

英文管线走 T1 编码，`≥ ≤ ≠ ≈ ∞` 在其中**没有定义**，输入会被静默丢弃。类里给这五个
字符补了数学映射（`newunicodechar`），其余箭头与单位符号由 `textcomp` 自带。

中文必须用 XeLaTeX：pdfLaTeX 处理 CJK 会得到缺字或乱断的 PDF。类里检测到
`zh + pdfLaTeX` 会**直接报错**并给出命令——错得早比错得隐蔽好。

## 4. 会被「静默吞掉」的东西，都从类层面堵掉

这一条是设计里最花心思的部分，因为这三种错误都不会报错：

1. **关键词**：`\keywords{}` 立即排版，不再依赖「必须写在 abstract 环境内」的隐含约定。
2. **附录引用**：`\appendix` 里做 `\clearpage` 与 `\crefalias{section}{appendix}`，
   因此正文中早先写的 `\appref{}` 也会输出「附录 A」，而不是模糊的「节 A」。
3. **中文缺字**：见上一条，直接报错。

## 5. 交叉引用为什么要两套宏

`cleveref` 的英文习惯是「section 3」，中文是「第 3 节」——语序相反。
用 `\crefformat` 硬改中文时，`#1`（类型名）取不到值，超链接会变成空链接
（hyperref 会警告 `Suppressing empty link`），读者点不动。

因此拆成两条：图表用 `\cref`（中文「图 1」语序天然正确），章节用 `\secref`
（`第~\ref{}~节`）。两者都能正确超链接。

## 6. 有意不做的事

| 不做 | 原因 |
|---|---|
| 学位论文格式 | 学校模板（如 hithesis）是硬约束，本工具包不该也不能替代 |
| 内置会议 `.sty` | NeurIPS/ICLR/ACL 的模板有各自许可，应让作者从官方获取 |
| `unicode-math` | 会改变用户既有公式的写法；本模板选择保守的 `mathpazo` + `amssymb` |
| 双栏 / 封面 / 彩色主题 | 想保持单一、可预测的观感；需要时按 `docs/adoption.md` 自行扩展 |
| 自动排版检查 | CI 只验证「能编译」，好不好看必须人眼看——这条写进了发布清单 |

## 7. 版本策略

语义化版本 + git tag。`\reportsetup{version}`、CHANGELOG、tag 三者必须一致；
PDF 元数据由类自动同步，不需要另填。
