# 发布检查清单

按顺序过一遍，任何一项没过就不要发。

## 1. 事实与数字

- [ ] 摘要里的每个数字都能在正文表格里找到
- [ ] 每个基准写清 shots / CoT / 评测框架版本
- [ ] 基线是**自己重跑**的，或明确标注「引自原文」
- [ ] 算力披露：设备型号、数量、时长、利用率
- [ ] 数据规模：样本数、来源、是否含合成数据
- [ ] 失败与回滚如实记录（发散、崩溃、重启次数）

## 2. 可复现性

- [ ] 模型/数据链接可访问
- [ ] 训练与推理脚本可访问
- [ ] 评测脚本与报告里的数字同源
- [ ] 数据要么开源，要么说明获取方式与许可
- [ ] `\reportsetup{version}` 与 git tag 一致

## 3. 文档质量

- [ ] 每张图表都在正文被 `\cref` 引用
- [ ] 没有孤行/孤页（一张图独占一页而正文不接）
- [ ] 参考文献没有 `?`，URL 可点
- [ ] Limitations 是具体条目，不是「受限于算力」一句带过
- [ ] 作者与致谢写明具体贡献

## 4. 合规

- [ ] 代码/权重/数据的许可明确（MIT / Apache-2.0 / CC BY 4.0 …）
- [ ] 没有搬运他人图表、logo、商标
- [ ] 涉及人类数据的部分有说明；涉及第三方模型输出符合其条款
- [ ] 双盲投稿时：作者、致谢、仓库链接已匿名化

## 5. 构建

- [ ] 干净构建成功：`.\build.ps1 -Clean` 后重跑
- [ ] `main-en.log` / `main-zh.log` 里没有 `!` 开头的错误
- [ ] 没有 `Missing character`（尤其是中文与 `≥ ≤ ≠ ≈ ∞`）
- [ ] 没有 `Overfull \hbox`（超出 1pt 的要看一眼）
- [ ] PDF 元数据正确：`pdfinfo main-zh.pdf` 看 Title/Author
- [ ] 页数、字号符合目标渠道
- [ ] 在另一台机器或 CI 上也能编译（防止本地字体依赖）

## 6. 发布动作

- [ ] 打 tag：`git tag -a v1.0.0 -m "..."` 并推送
- [ ] Release 附上两份 PDF（CI 的 tag 流水线会自动做）
- [ ] 更新 CHANGELOG
- [ ] 在 README 里更新版本徽章与引用格式
